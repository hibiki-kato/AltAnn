# Original UniAnn fixtures

`uniann-fixture.gff3` and `uniann-fixture.trace` were generated by Aleksey
Zimin's seven-state UniAnn executable, built from upstream commit
`91477a69e1a949fed082c4662b348d9a7a91ca2b`. They are independent of AltAnn's
decoder. The synthetic sequence and scores come from the unmodified default
`write_fixture` function in `tests/fixtures.py`.

To regenerate, call `write_fixture` in a temporary directory, then run the
upstream binary with these positional arguments:

```text
uniann fixture.fa emissions.txt gt.txt ag.txt atg.txt stop.txt
```

Save stdout as `uniann-fixture.gff3`. Retain the `dp` and `bt` rows from stderr
as `uniann-fixture.trace`, preserving row order and the final newline. There
are 1,200 positions and 2,400 trace rows. These logs retain UniAnn's original
integer serialization; AltAnn must reconstruct exact scores from the inputs.

The reverse-mode checks use the same oriented synthetic input and trace,
then verify output reflection independently. The real S. pombe validation
uses separately scored forward and reverse-complemented sequences; see
[validation](../../docs/validation.md).

# Local coding-frame fixtures

`coding-frame/` was generated by the actual UniAnn coding-frame converter,
wrapper, and native decoder from upstream commit
`6fe3d46efacf1f900789a4cfa6d103c69dfe6ac0`. AltAnn was not used to generate
the emissions, transitions, reference annotation, or Viterbi trace.

To regenerate from AltAnn, run:

```sh
python3 tests/generate_coding_fixture.py --uniann ../UniAnn
```

Regeneration requires g++, Bash, Perl, and a runnable `UniAnn/gffread`;
`--gffread /path/to/gffread` overrides that binary. The generator stages a
freshly compiled upstream decoder and unchanged upstream scripts in a
temporary directory, then runs `uniann.sh -f sequence.fna -c coding.txt -s
scores.txt`. It removes the emission cache before running the wrapper.
`provenance.json` records the source commit, source hashes, gffread version,
and the designed CDS coordinates. Tests consume these committed artifacts
using Python and the compiled AltAnn core; Perl and UniAnn are not runtime
test dependencies.

The 1,740-base sequence contains three genes whose initial absolute frames
are 0, 1, and 2, with intron lengths 60, 61, and 62 bases. Each first CDS is
121 bases, so the second CDS has GFF phase 2. The resulting native frame
transitions are E0→E0, E1→E2, and E2→E1. Each intron has an alternative
acceptor three bases downstream. `coding.txt` contains synthetic, normalized
four-class local-frame probabilities; the emitted `out.ps.txt` includes the
current upstream temperature transform, absolute-frame mapping, stop mask,
and nucleotide column. The sparse scores come from the wrapper's actual
site-score preprocessing.

`uniann.gff3` retains the native CDS/intron output; `uniann.filtered.gff3`
retains the wrapper's gffread annotation and minimum-CDS filtering output.
`uniann.trace` retains all 3,480 native `dp` and `bt` rows, with progress
messages removed. The tests check both forms of upstream annotation,
trace replay against rerunning Viterbi, direct path-score sums, alternative
acceptor score differences, coding lengths and phases, and reflected reverse
coordinates. Reverse checks use the same oriented scores and change output
mapping only; they do not claim that upstream predicts both strands in one
coding-frame file.

# Bowen coding-frame contract diagnostic

`bowen-contract/` uses actual functions from Bowen's `cnn-mamba` commit
`809f74379efccf70ee7fd876dc95aabe5a4b0ea7` and the unchanged UniAnn converter,
wrapper, and freshly compiled native decoder at
`6fe3d46efacf1f900789a4cfa6d103c69dfe6ac0`. It is a pinned diagnostic of those
sources, not an endorsement of their discrepancies. The older `coding-frame/`
fixture above manually supplies the converter's expected local labels; this
fixture independently obtains Bowen's actual labels from `build_phase_track`.

Regenerate from AltAnn with a Python interpreter containing NumPy, pandas,
and torch, plus g++, Perl, Bash, and a runnable `UniAnn/gffread`:

```sh
python3 tests/generate_bowen_fixture.py --bowen ../cnn-mamba --uniann ../UniAnn
```

The generator executes the unchanged AST of `build_phase_track` with NumPy
as its only global dependency, avoiding the preparation module's unrelated
`pysam` import. It applies the actual `apply_temperature_numpy` function to
deterministic synthetic logits, then invokes the actual TSV exporter. It uses
the published human checkpoint's temperature `1.2288177735743935` to exercise
the transform; this does not establish calibration validity for another model
or organism. No checkpoint, neural inference, trained accuracy assessment, or
additional calibration in AltAnn is involved. All source hashes, revisions,
logit profiles, calibrated profiles, and actual phase labels are recorded in
`provenance.json`. The generator imports or invokes no AltAnn code.

The 1,700-base sequence reuses the three-gene geometry above, trimming 40
terminal noncoding bases. It covers CDS starts in all three absolute frames,
intron lengths modulo three of 0/1/2, and second-exon GFF phase 2. Bowen's
phase-0 CDS labels begin `0,1,2`, whereas the pinned converter maps local class
`i` at zero-based position `n` to `(n-i-1) % 3`; the emission peak therefore
lands one absolute frame behind `(n-i) % 3`. Its independent per-column
temperature-7 transform additionally changes the already normalized,
multiclass-calibrated probabilities without restoring their sum to one.

`exported.tsv` preserves the real eight-column, headered exporter output.
`coding.txt` removes only its header, retaining `predicted_state`, which the
converter ignores. `header-diagnostic.txt` retains the first three rows from
directly feeding the headered TSV to the converter; the recorded result has
1,701 emission rows because that converter does not skip the header. The
normal processed artifacts use the headerless input. Tests check this
diagnostic and ensure AltAnn rejects an extra emission position.

The saved native GFF and trace and the `out.*.txt` files support downstream
regressions: AltAnn's trace replay matches rerunning Viterbi, reference path
scores equal literal float32 emission and transition sums, and alternatives
have valid CDS sequences/phases with reflected minus-strand output. Those
checks demonstrate consistent consumption of UniAnn's emitted scores;
they do not resolve the upstream frame rotation or duplicated scaling.
Minus-strand phase labels are checked with the real preparation function on
reflected intervals; decoder reverse checks use the same oriented scores and
reflect annotation coordinates, without claiming raw minus export support.
Tests require only the Python standard library and the compiled AltAnn core;
the generator's optional dependencies are unnecessary for normal testing.

# Corrected Bowen score contract

The older `coding-frame/` and `bowen-contract/` fixtures freeze **unpatched**
UniAnn `6fe3d46` behavior. Regenerate them only from a clean checkout of that
revision, not the locally corrected working tree. Their generators record
source hashes but do not enforce revision cleanliness. Use the generator
below for the corrected converter; keep historical artifacts unchanged.

`bowen-corrected/` replays the exact frozen `bowen-contract/exported.tsv`,
`sequence.fna`, and `scores.txt` through the corrected working-tree UniAnn
converter and wrapper, with a freshly compiled upstream native decoder.
The archived `bowen-contract/` artifacts remain unchanged. This new fixture
contains synthetic logits exported by Bowen's real exporter; it contains no
real S. pombe model predictions and performs no neural inference.

```sh
python3 tests/generate_corrected_fixture.py --uniann ../UniAnn
```

The generator requires only Python's standard library, g++, Bash, Perl and
a runnable `UniAnn/gffread` (override with `--gffread`). It feeds the headered
TSV directly to the corrected wrapper and deliberately supplies a stale
emission cache, verifying regeneration. Provenance records the original
Bowen revision, UniAnn base revision, frozen-input hashes, modified source
hashes and gffread hash. The output contains exactly 1,700 emission rows;
local codon-base class `i` at position `n` peaks at `(n-i) % 3`, and noncoding
scores use exported probabilities without the former temperature-7 transform.
The existing upstream coding gate and stop masking remain in use.

Inherited downstream regression checks compare saved native trace replay
with rerunning Viterbi on both output strands, sum literal float32 emission
and transition scores, and validate alternative CDS lengths, phases and
start/stop codons. Reverse checks reflect the same oriented fixture's output;
they do not substitute for inference on a real reverse-complemented genome.

# Real S. pombe biological findings

`spom_prediction_internal_stop.json` freezes original-genome DNA and GFF CDS
coordinates from actual model outputs on both strands, with provenance. The
validator detects stops assembled across exon junctions without trimming each
segment's phase bases. These findings are a shared UniAnn model limitation.

`spom_prediction_start_overlap.json` freezes the real minus-strand start/donor
overlap case. Its contiguous genomic ATGT contains valid ATG and GT motifs,
but splicing the two-base first exon gives an ATC CDS start. Native UniAnn and
AltAnn reproduce the same annotation under forced-path diagnostic emissions;
those emissions are synthetic and separate from the real accuracy evaluation.

The full actual CNN-Mamba predictions, six native traces, annotations, command
logs and reference metrics remain ignored under
`example/results/cnn-mamba-spom-validation/gpu-run-20261013/`, as described in
`docs/spom-validation.md`.
